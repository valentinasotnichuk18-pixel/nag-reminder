# Тест-план: Тук-тук v1.0

## 1. Об'єкт тестування

**Тук-тук** це Android-застосунок нагадувань, який повторює нагадування із заданим інтервалом, поки користувач не позначить справу як виконану.

| Параметр | Значення |
|---|---|
| Версія | 1.0.0 (development build) |
| Платформа | Android |
| Стек | React Native, Expo SDK 57, SQLite, expo-notifications, expo-calendar |
| Зберігання даних | Локально на пристрої, без сервера і без акаунтів |

## 2. Мета

1. Підтвердити, що основна функція (повторювані нагадування до натискання "Готово") працює надійно.
2. Перевірити коректність роботи з датами, часом і календарем.
3. Перевірити поведінку на граничних значеннях (ліміт Android на 500 запланованих сповіщень).
4. Підготувати застосунок до закритого тестування в Google Play.

## 3. Обсяг

### У межах тестування

| Модуль | Що перевіряємо |
|---|---|
| Завдання | Додавання, редагування, видалення, валідація, дедлайн |
| Нагадування | Інтервал, години роботи, наростання тексту, кнопки "Готово" і "Через 15 хв" |
| Виконання | Миттєве закриття, плашка "Виконано за...", "Повернути" |
| Налаштування | Інтервал, години, збереження, валідація |
| Зведення | Режими "кожні N год" і "у певний час", вміст, події дня |
| Події | Створення, редагування, видалення, синхронізація з Google Календарем |
| Історія | Виконані справи, минулі події, повернення, очищення |
| Довідка | Перший запуск, повторне відкриття, дозволи |
| Ліміт сповіщень | Поведінка при переповненні, спільне нагадування |
| Персистентність | Збереження даних після перезапуску і оновлення |

### Поза межами тестування

- iOS (застосунок лише для Android)
- Автоматизовані тести (заплановано у v2)
- Навантажувальне тестування
- Реєстрація і хмарна синхронізація (заплановано у v2)

## 4. Підхід

| Вид | Опис |
|---|---|
| Функціональне | Тест-кейси і чеклісти за кожним модулем |
| Регресійне | Повторна перевірка попередніх модулів після кожної зміни коду |
| Граничні значення | Ліміт сповіщень, межі годин роботи, дедлайн у минулому |
| Негативне | Порожні поля, некоректні діапазони часу, відмова в дозволах |
| Дослідницьке | Вільне використання застосунку протягом дня |
| Ретест | Перевірка виправлених багів |

Кожен крок розробки закривався чеклістом. Наступний крок починався лише після проходження всіх пунктів.

## 5. Тестове середовище

| Параметр | Значення |
|---|---|
| Пристрій | Android-смартфон (реальний пристрій, не емулятор) |
| Збірка | EAS development build |
| Мережа | Wi-Fi (для підключення до сервера розробки) |
| Календар | Google Календар, синхронізований на пристрої |

Чому реальний пристрій: поведінка фонових сповіщень і оптимізації батареї на емуляторі відрізняється від реальних телефонів.

## 6. Критерії

**Початок тестування:** збірка встановлюється і запускається, функція готова до перевірки.

**Завершення:**
- усі тест-кейси з пріоритетом High пройдено;
- немає відкритих багів з пріоритетом High;
- регресія основних сценаріїв пройдена після останньої зміни.

## 7. Ризики

| Ризик | Вплив | Як зменшуємо |
|---|---|---|
| Android "присипляє" застосунок і глушить сповіщення | Нагадування не приходять | Підказка в довідці вимкнути оптимізацію батареї |
| Ліміт 500 запланованих сповіщень | Частина нагадувань не планується | Пріоритизація і спільне нагадування для решти |
| Зміни в бібліотеках Expo | Застарілі функції перестають працювати | Перехід на новий API календаря, ізоляція викликів |
| Текст сповіщення записується наперед | Відносний час ("до 18:00") стає неактуальним | У сповіщеннях лише абсолютні дати |
